十四、第六次改动（01:05 追加）：全自动成句 + 智能体升级 + 手机扫码
======================================================================
你的三条批评都成立，这次是针对性改：

1) 「提交智能体」要动手点 —— 手在比划，按不到
   改法：新增"停顿自动成句"。每识别出一个词，就把计时器往后推；
        停手 auto_pause_sec(默认 2.5 秒) 后自动执行：
        当前词串 -> 调智能体润色 -> 推 TFT 屏 -> 落库成一条整句记录 -> 清空缓冲准备下一句
        全程零点击。原按钮保留，改名「重新润色(手动)」「立即上屏(手动)」作兜底
        (智能体临时不可用/想强制重来时用)

2) 网页/屏幕是不是手动提交才同步 —— 不是，本来就自动
   实测链路与延迟：
     出一个词         -> 立刻写入数据库 records 表，同时 /api/display 推终端
     网页看板         -> 每秒轮询 /api/state           => 1 秒内出现
     网页历史记录     -> 每 3 秒轮询 /api/records       => 3 秒内出现
     ESP32 TFT 屏     -> 每 2 秒轮询 /api/terminal/esp  => 2 秒内更新
   所以"比一个再见，网页上就有再见"是既成事实，不需要任何按钮。
   手机扫码打开的就是同一个网站同一份数据（不是另一套），不存在"不同步"。

3) 智能体只会拼句子，太水
   升级内容：
     · 接收上文(context, 最近 3 句)：能消解指代和省略
       实测: 输入 [他, 去] + 上文"我妈妈生病了，现在在医院" -> "他去医院了。"
     · 手语语序理顺: [我, 吃饭, 去] -> "我去吃饭。"
     · 语气判断与标点: [你, 明天, 有空] -> "你明天有空吗？" 标签 询问
     · 新增 short 字段(<=12字 上屏短句)：TFT 只有一行，长句放不下
       例: "我明天去医院帮忙。" 上屏显示 "明天去医院帮忙"
     · 仍严格约束不许编造人名/地点/数字/时间

  gui/gui_app.py        + auto_finalize / auto_pause_sec / auto_agent 三个配置
